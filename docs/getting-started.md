# Getting started

This page takes you from a fresh clone to a running game, then to the tests. Every third-party
library is downloaded and pinned by the build: you only install a compiler, CMake and, on Linux,
a few low-level system libraries.

## Requirements

| Platform | Tested with | Install |
| --- | --- | --- |
| Fedora | GCC, Ninja | `sudo dnf install cmake ninja-build gcc-c++ libX11-devel libXrandr-devel libXcursor-devel libXi-devel systemd-devel mesa-libGL-devel` |
| Ubuntu | GCC, Ninja | `sudo apt install cmake ninja-build g++ libx11-dev libxrandr-dev libxcursor-dev libxi-dev libudev-dev libgl1-mesa-dev` |
| Windows 10/11 | Visual Studio 2022 | CMake 3.21+ and the "Desktop development with C++" workload |

You need CMake 3.21 or newer and a C++20 compiler (GCC 11+, Clang 14+ or MSVC 2022). The X11,
OpenGL and udev packages above are what SFML needs to open a window and read the keyboard; the
server alone does not need them (see `RTYPE_BUILD_CLIENT` below).

## Build

On Linux:

```sh
export CPM_SOURCE_CACHE=$HOME/.cache/CPM   # download dependencies once, reuse them in every build
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

On Windows (Visual Studio generator):

```powershell
cmake -S . -B build
cmake --build build --config Release
```

The first configure downloads Asio, SFML and Catch2 (a few minutes); later ones reuse the cache.
`r-type_server` and `r-type_client` are written at the repository root, test programs and the
test bot in `build/bin/`.

| CMake option | Default | Effect |
| --- | --- | --- |
| `RTYPE_BUILD_TESTS` | `ON` | builds the Catch2 tests |
| `RTYPE_BUILD_CLIENT` | `ON` | builds the graphical client; `OFF` builds the server without downloading SFML |
| `RTYPE_BUILD_EXAMPLES` | `OFF` | builds the [headless Pong](pong-tutorial.md) engine example |
| `RTYPE_WARNINGS_AS_ERRORS` | `OFF` | turns compiler warnings into errors, as the CI does |

## Play

Start the server, then one client per player (up to four), each in its own terminal:

```sh
./r-type_server -p 4242
./r-type_client -h 127.0.0.1 -p 4242
```

In the client menu, choose the game mode and the difficulty, then **JOIN THE GAME** with
**Enter**. Arrow keys move, **Space** fires, **F2** toggles auto-fire, **Escape** goes back to the
menu. The keys can be changed in the menu (CONTROLS); see the [demo page](demo.md) for every
command and key.

To play on a local network, start the server on one machine and give its address to `-h` on the
others. The server listens on UDP: allow the port in the firewall of the server machine.

| Program | Option | Default | Meaning |
| --- | --- | --- | --- |
| `r-type_server` | `-p port` | `4242` | UDP port to listen on |
| `r-type_client` | `-h host` | `127.0.0.1` | server address |
| | `-p port` | `4242` | server port |
| | `--assets dir` | `assets/` next to the executable | sprites, font and sounds |
| | `--mute` | off | start without sound |
| | `--help` | | print usage without opening a window |

Both programs print their usage and exit with code 84 on an invalid option.

## Play without a window: the test bot

`r-type_bot` connects headless players that fly at random, fire, and print what they see once per
second. It is the quickest way to load the server or check it from a machine without a display.

```sh
./build/bin/r-type_bot -h 127.0.0.1 -p 4242 -n 4 -d 30   # 4 bots for 30 seconds
```

`-n` goes up to 8: bots beyond the fourth show the server refusing a full game.

## Run the tests

```sh
ctest --test-dir build --output-on-failure                  # Linux
ctest --test-dir build -C Release --output-on-failure       # Windows
```

| Suite | Covers |
| --- | --- |
| `engine_tests` | registry, sparse arrays, fixed timestep, event bus, scheduler, logger, core tools |
| `game_tests` | input, movement, bounds, enemy waves, collisions, damage, score, lives, cleanup |
| `network_tests` | serializer, thread-safe queue, UDP socket, packet codec with truncated, oversized and random datagrams |
| `server_tests` | sessions, game world, full server against real UDP clients (join, refuse, timeout, flood) |
| `client_tests` | command line validation, starfield speed independent of the frame rate |

None of them opens a window or needs a sound card, so they also run on a headless machine.

To try the game on a bad network (Linux), add loss and delay on the loopback interface, then
remove them:

```sh
sudo tc qdisc add dev lo root netem loss 2% delay 150ms
./build/bin/r-type_bot -n 4 -d 30
sudo tc qdisc del dev lo root
```

## Read this site locally

The site is generated by [MkDocs](https://www.mkdocs.org/) with the Material theme from the
Markdown files in `docs/`.

```sh
python3 -m venv .venv
.venv/bin/pip install -r docs/requirements.txt
.venv/bin/mkdocs serve            # http://127.0.0.1:8000, reloads on every save
.venv/bin/mkdocs build --strict   # what the CI runs: a broken link fails
```

To add a page, create it in `docs/` and add it to `nav:` in `mkdocs.yml`; the strict build fails
on a page missing from the menu.
